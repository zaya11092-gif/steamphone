# DroidDeck for iOS — Hybrid plan (local VM + streaming + GPU R&D track)

## Goal

An open-source, sideloadable `.ipa` in `C:\Users\user\Documents\steamphone` that ports the DroidDeck experience (SteamOS-like Steam Big Picture gaming) to iPhone, built entirely on open-source components, with CI-built releases — following DroidDeck's own release model.

**Why a VM at all:** DroidDeck on Android runs an ARM64 Linux runtime through **proot** on Android's kernel (needs `ptrace`/`fork()`, forbidden on iOS) with FEX host-thunks calling Android's Vulkan driver directly. iOS's sandbox makes that architecture impossible, so local execution must go through **full-system QEMU emulation** (UTM's approach): the guest brings its own kernel, so fork/JIT/ptrace work *inside* the VM.

**GPU reality (agreed):** QEMU on iOS has no host GPU backend (virgl/Venus need host OpenGL/Vulkan; iOS gives apps Metal only). v1 therefore ships two ways to play — local software-rendered VM + hardware-speed streaming — plus a real engineering track toward a Metal-reaching paravirtual GPU.

## Milestones

**M1 — Engine scaffold, IPAs building.** Shallow-clone UTM at a pinned tag; keep engine layers, drop their frontend; stub DroidDeck UI; adapt UTM's CI scripts. Sysroots built for `ios-arm64` (JIT edition — needs one-time SideStore/AltStore "Enable JIT", analogous to DroidDeck's own required Android tweak) and `ios-tci-arm64` (SE edition — installs anywhere, slower). *Exit: both unsigned IPAs as CI artifacts.*

**M2 — DroidDeckOS guest boots.** CI workflow builds Arch Linux ARM64 image via qemu-user-static chroot: FEX-EMU with host thunks (same recipe as the original project), x86_64 Steam client under FEX auto-starting in `-tenfoot` (Big Picture), minimal compositor (cage/weston; gamescope needs KMS we don't have), PipeWire→QEMU audio. Kernel+DTB for `virt`, compressed qcow2 (~3–5 GB) published as release asset.

**M3 — Local playability, tuned.** Software rendering maximized: Mesa llvmpipe + lavapipe (Vulkan-on-CPU so DXVK/vkd3d can initialize for Wine/Proton titles), LLVM codegen options, vCPU/RAM tuning (`com.apple.developer.kernel.increased-memory-limit` entitlement; ~5 GB VM on 8 GB devices). Input: touch-as-pointer, virtual keyboard, and **GameController framework → virtio-input** so MFi/Xbox/PS controllers drive Big Picture. In-app resumable image downloader. *Exit: boot → Steam login → navigate store → launch a lightweight title, end-to-end on device.*

**M4 — Streaming mode (hardware-speed gaming day one).** Embed moonlight-common-c; implement the iOS side: VideoToolbox H.264/HEVC/AV1 decode → Metal presentation, AudioUnit output, GameController→GameStream input, mDNS host discovery, PIN pairing. Home screen gets two session types: "DroidDeckOS (local)" and "Stream from your PC" (Sunshine/GameStream host). *Exit: 60 fps Steam Big Picture streamed to iPhone with controller.*

**M5 — GPU acceleration R&D track (go/no-go gated, target: later release).** The only precedent-backed route is Google's **gfxstream** (guest drivers in mainline Mesa since Sept 2024; the QEMU-derived Android Emulator reaches Metal on Apple Silicon via its host layer). Gates:
- **G0:** MoltenVK-on-iOS feature audit vs gfxstream/Venus host requirements — decide gfxstream-over-MoltenVK vs Venus-over-MoltenVK.
- **G1:** standalone iOS harness: MoltenVK + gfxstream host renderer drawing via a local socket (guest side simulated).
- **G2:** integrate as virtio-gpu backend in our utmapp/QEMU fork; guest Mesa gfxstream driver renders.
- **G3:** perf bar (baseline scene ≥ 30 fps in-guest) → fold into the shipped image.
Any gate fails → findings documented, streaming remains the high-performance path. Even at success, TCG CPU emulation stays a bottleneck for heavy titles — stated plainly in the README.

**M6 — v0.1.0 release.** CI builds `DroidDeck-JIT.ipa`, `DroidDeck-SE.ipa`, `DroidDeckOS-arm64.img.zst`; README covers sideloading (SideStore/AltStore/Sideloadly, JIT toggle, 7-day free-signing refresh), performance expectations, and GPL attribution (project GPL-3.0; UTM Apache-2.0, QEMU GPLv2, moonlight-common-c GPL-3.0, DroidDeck GPL-3.0 — NOTICE files preserved).

## Honest performance expectations (stated in-app and README)

- **Streaming:** full speed — this is how modern Steam games are actually playable on iPhone in v1.
- **Local JIT edition:** desktop/Steam UI usable-slow; lightweight/2D/older games marginal; modern 3D unplayable (software GL + emulated CPU).
- **Local SE edition:** slower fallback for zero-extra-steps installs. Target 8 GB-RAM iPhones (15 Pro+).

## Key risks & mitigations

- utmapp dependency-script drift → pin UTM tag; cache Sysroots in Actions (iteration builds ~15 min).
- FEX-under-TCG instability → Box64 fallback, or x86_64 guest profile, decided empirically in M3.
- M5 is research, not a promise → hard go/no-go gates; v1 value doesn't depend on it.
- You'll need a GitHub account/repo for CI (Windows can't run Xcode); everything up to first CI run is local authoring. `gh` CLI used to create the repo and manage Actions.
